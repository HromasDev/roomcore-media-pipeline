# roomcore-media-pipeline

Пет-проект: пайплайн загрузки и обработки изображений для мессенджера [roomcore](https://roomcore.ru). Вынесен в отдельный репозиторий как самостоятельное демо: файлы идут в S3-совместимое хранилище напрямую от клиента, а обработка выполняется асинхронно через очередь.

Что здесь есть:

- **S3 (MinIO)** — загрузка оригиналов по presigned URL, клиент отправляет файл напрямую в хранилище, бэкенд его не проксирует. Оригиналы лежат в приватном бакете `uploads`, превью в бакете `previews` с публичным чтением.
- **Kafka API (Redpanda)** — после загрузки бэкенд публикует событие `image.uploaded` в топик, воркер читает его и обрабатывает файл. Redpanda — Kafka-совместимый брокер без ZooKeeper и JVM, клиент использует обычный `kafkajs`.
- **Воркер на sharp** — делает три превью (320, 800, 1600 px, WebP) и пишет статус в PostgreSQL.
- **API на Hono** (Bun), **PostgreSQL**, **Docker Compose**, тесты на `bun test`.

Это учебный проект, не продакшен: без авторизации, без CDN, одна нода брокера.

## Схема

```
клиент ── POST /uploads ─────────────► api ── запись в PostgreSQL (pending)
   ◄── fileId + presigned PUT URL ──────┘
клиент ── PUT файл ──────────────────► S3 (бакет uploads)
клиент ── POST /uploads/:id/complete ► api ── проверка объекта в S3
                                           └─ статус queued + событие image.uploaded ► Kafka (3 партиции)
                                                                                         │
                                           воркер (группа media-worker) ◄────────────────┘
                                             ├─ скачивает оригинал из S3
                                             ├─ sharp: 320 / 800 / 1600 px, WebP
                                             ├─ кладёт превью в бакет previews
                                             └─ статус done в PostgreSQL
клиент ── GET /images/:id ───────────► статус и ссылки на превью
```

Решения:

- **В Kafka идёт только лёгкое событие** (`fileId`, `originalKey`), сам файл в шину не кладётся.
- **Ключ сообщения — `fileId`**: события одного файла попадают в одну партицию и идут по порядку.
- **At-least-once**: offset коммитится после успешной обработки, поэтому при падении воркера событие придёт заново. Повторное событие для готового файла пропускается.
- **Битый файл** получает статус `failed` с текстом ошибки и не блокирует партицию.
- **Масштабирование**: у топика 3 партиции, воркеры одной группы делят их между собой: `docker compose up -d --scale worker=3`.
- **Имя файла от клиента в ключ S3 не попадает**, ключ строится из `fileId` и типа содержимого. Принимаются только JPEG, PNG и WebP.

## Запуск

Нужны Docker и Bun.

```bash
docker compose up -d --build
```

Поднимутся PostgreSQL, MinIO, Redpanda, API (`:3000`) и воркер. Бакеты и топик создаются при старте.

Сквозная проверка (загрузка по presigned URL, событие, превью), запускается внутри сети compose:

```bash
docker compose run --rm -e API_URL=http://api:3000 --no-deps api bun run scripts/demo.ts
```

Порты на хосте: API `3000`, MinIO `19000` (консоль `19001`), PostgreSQL `127.0.0.1:55434`, Kafka `9092`. Они подобраны так, чтобы не пересекаться со стандартными `5432`, `9000` и другими.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/uploads` | тело `{ "contentType": "image/png" }`, ответ `{ fileId, uploadUrl, expiresIn }` |
| POST | `/uploads/:id/complete` | проверяет файл в S3, публикует событие, ответ `202 { status: "queued" }` |
| GET | `/images/:id` | статус (`pending`, `queued`, `processing`, `done`, `failed`) и ссылки на превью |
| GET | `/health` | проверка живости |

## Тесты

```bash
bun install
bun test
bun run typecheck
```

Тесты работают на фейках хранилища и репозитория, без сети и Docker: ключи и валидация, полный цикл API, отказ при незагруженном файле, воркер (три превью, идемпотентность, битый файл).

## Структура

```
src/app.ts           маршруты Hono (зависимости передаются снаружи)
src/api.ts           запуск API
src/worker.ts        consumer Kafka
src/process-image.ts обработка одного события (sharp)
src/storage.ts       S3: presigned URL, чтение, запись, создание бакетов
src/kafka.ts         клиент, топик, producer
src/repo.ts          PostgreSQL: таблица images и статусы
src/keys.ts          ключи объектов, разрешённые типы
src/events.ts        схема события
tests/               тесты
scripts/demo.ts      сквозная проверка
```
